# Рецензія коду algo-illust (стан коміту 3fac554)

Рядки вказано для вихідного коміту 3fac554. Позначка **[В]** — виправлено в пункті 3, **[Н]** — свідомо не змінено (причину наведено).

## Коректність

1. `src/utils/sorts/sorts.ts:198` — `quickSortLocal` пропускає сортування, якщо весь масив уже впорядкований **за зростанням** (`isSorted(items, true)`), незалежно від `isASC`. Масив `[1,2,3]` у режимі Desc лишається невідсортованим, а лічильник кроків показує 0. **[В]** — перевірка враховує напрямок (саму перевірку залишено, щоб не подовжувати анімацію за зростанням).
2. `src/utils/sorts/sorts.ts:114-118` — сортування підрахунком індексує `count[arr[i] - min]` дробовими значеннями (варіанти 1, 3, 12, 13, 16 дають дроби) → результат заповнюється `0`/`undefined`, користувач бачить «відсортований» некоректний масив. `Math.max(...arr)` на великих масивах кидає `RangeError`. Крім того, результат пишеться лише в копію `sorted` і не повертається в `arr` — без `render` масив лишається невідсортованим, на відміну від решти алгоритмів. **[В]** — зрозуміла помилка для нецілих значень, яку показує компонент; результат копіюється в `arr`.
3. `src/components/sorts/SortComponent.tsx:41` — час обчислюється як `total - steps * delay`, але кількість викликів `render` не дорівнює кількості кроків (bubble/selection рендерять ще й у кінці проходу, merge рахує злиття) → «Time taken» від'ємний або завищений. **[В]** — віднімається фактичний час очікування анімації.
4. `src/components/sorts/Params.tsx:12` + `src/pages/SortPage.tsx:14` — селектор швидкості показує значення 400 мс (пункт «8»), а фактична затримка до першої зміни — 250 мс. **[В]** — одна константа `DEFAULT_DELAY`; стартова швидкість тепер відповідає показаній.
5. `src/utils/data_structures/test.ts:15,17` — `findIndex(...) || 0` / `|| ds.length`: індекс 0 трактується як «не знайдено», тож для максимуму на позиції 0 «El after max» завжди `null`. **[В]** (`??`).
6. `src/utils/sorts/generateArray.ts:62-63` — `findIndex(...) || 0` не ловить `-1`, а `findLastIndex(...) || 1` підміняє валідний індекс 0 → неправильний зріз у варіанті 9. **[В]**
7. `src/utils/sorts/generateArray.ts:99` — результат `cities.filter(...)` відкидається, фільтр варіанта 14 не працює. **[В]**
8. `src/utils/searches/searches.ts:92,104` — `bmSearch` завжди повертає 0 кроків. **[В]**
9. `src/components/searches/Binary.tsx:55` — `search(array, value)` ігнорує `value`, у `binarySearch` передано літерал `0`. **[В]**
10. `src/pages/SortPage.tsx:15` (також `SearchPage.tsx:12`, `DataStructuresPage.tsx:34`) — тип активної сторінки береться з `window.location.href.split("/").pop()`: з кінцевою `/`, `?query` чи `#hash` підсвітка навігації зникає. **[В]** — через `useLocation`.

## Надійність

11. `src/utils/workerBuilder.ts:3-6` + `src/components/sorts/SortsTable.tsx:37` — воркер будується з `fn.toString()`. У production-збірці тіло функції посилається на мініфіковані змінні модуля (`fe` = `generateRandomArray`, `se`, регенератор), яких у blob-воркері немає → `ReferenceError`, таблиця порівняння назавжди показує «Sorting...». Крім того, `super(worker)` створює зайвий `Worker` з URL, рівним тексту функції (мережевий запит на 404). **[В]** — модульний воркер Vite (`?worker`).
12. `src/components/sorts/SortsTable.tsx:37-48` — кожен запуск створює новий потік, який ніколи не завершується (`terminate` відсутній); після виходу зі сторінки воркер працює далі (bubble на 10⁶ елементів — хвилини CPU). **[В]**
13. `src/components/sorts/SortsTable.tsx:40-43` — побічний ефект `setIsSorting` усередині функції-оновлювача стану (у StrictMode викликається двічі) і замикання на застарілий `sortsToRun`. **[В]**
14. `src/components/sorts/SortComponent.tsx:38` (також `KMP.tsx:39`, `BM.tsx:39`) — `new Promise(async () => …)`: проміс ніколи не завершується, виняток (напр. з `countingSort`) стає unhandled rejection, а `isSorting` лишається `true` → сторінка назавжди відповідає «Please wait for the current sorting to finish». **[В]** (`try/finally`).
15. `src/components/sorts/SortComponent.tsx:30-34` — немає скасування при розмонтуванні: при перемиканні алгоритму під час анімації старий алгоритм продовжує змінювати спільний масив під назвою нового. **[В]**
16. `src/pages/SortPage.tsx:21-26` — відмова `generateArray` (мережеві варіанти 8, 14) лишає `loading = true` назавжди («Fetching data...»). **[В]**
17. `src/pages/Home.tsx:19` — глобальний `window.onkeydown` не знімається при розмонтуванні: обробник лишається на всіх сторінках, перезаписує будь-який інший `window.onkeydown` і на кожне натискання викликає `setState` розмонтованого компонента; таймери (рядки 15, 38) не очищаються. **[В]**
18. `src/components/SizeForm.tsx:8` — довжина не обмежена зверху: `1e9` блокує вкладку (`generateRandomArray` у головному потоці) до вичерпання пам'яті. **[В]** — верхня межа.
19. `src/utils/sorts/sorts.ts:4-5` — модульні змінні `IS_ASC`/`STEPS` спільні для всіх викликів; два паралельні сортування (див. п. 15) псують лічильники одне одному. **[В]** — стан локальний для виклику.
