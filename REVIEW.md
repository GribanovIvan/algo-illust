# Рецензія вихідного коду (Аналіз дефектів)

У результаті аналізу кодової бази вебзастосунку `algo-illust` виявлено такі дефекти за категоріями:

## 1. Коректність (Correctness)

1. **`src/App.tsx`, рядок 33:**
   - *Дефект:* Використання `<BrowserRouter basename="/asd">`.
   - *Загроза в експлуатації:* Застосунок жорстко прив'язаний до фіктивного префікса шляху `/asd`. При переході користувача за стандартним кореневим маршрутом `/` застосунок повертає сторінку 404 замість відображення `Home`.

2. **`src/utils/sorts/sorts.ts`, рядки 4, 5, 81, 89, 171, 226:**
   - *Дефект:* Використання глобальних змінних рівня модуля `let IS_ASC = true;` та `let STEPS = 0;`.
   - *Загроза в експлуатації:* Функції `quickSort` та `mergeSort` не є реентерабельними (не є потокобезпечними). При одночасному запуску сортувань або зміні напрямку/параметрів під час роботи значення перезаписуються, що призводить до порушення напрямку сортування та некоректного підрахунку кроків.

3. **`src/utils/sorts/sorts.ts`, рядок 198:**
   - *Дефект:* У `quickSortLocal` захардкоджена умова `if (items.length > 1 && !isSorted(items, true))`.
   - *Загроза в експлуатації:* Прапорець порядку завжди `true` (за зростанням). Якщо користувач обрав сортування за спаданням (`isASC = false`), алгоритм або передчасно перериває роботу, якщо масив вже частково чи повністю відсортований за зростанням, або виконує некоректні рекурсивні виклики. Крім того, перевіряється довжина всього масиву, а не поточного сегмента.

4. **`src/utils/sorts/sorts.ts`, рядки 125–133 (`countingSort`):**
   - *Дефект:* Функція сортування підрахунком записує відсортовані елементи в окремий масив `sorted`, але ніколи не мутує вхідний масив `arr` і не повертає його.
   - *Загроза в експлуатації:* Для будь-якого виклику, що очікує сортування масиву in-place або передає масив за посиланням, вхідний масив залишається невідсортованим, що порушує контракт сортувальної функції.

5. **`src/utils/searches/searches.ts`, рядки 54–56 (`kmpSearch`):**
   - *Дефект:* При незбігу замість зсуву за таблицею префіксів без повернення індексу `i` виконується: `j = lps[j - 1]; i -= j; j = 0;`.
   - *Загроза в експлуатації:* Ручне відкочування індексу `i` ламає головний інваріант лінійного часу алгоритму Кнута — Морріса — Пратта. Це призводить до помилкового пропуску входжень шаблону або зациклення пошуку.

6. **`src/utils/searches/searches.ts`, рядки 92, 104 (`bmSearch`):**
   - *Дефект:* Функція повертає захардкоджене значення кроків `0` замість реального лічильника: `return [found, 0]`, `return [null, 0]`.
   - *Загроза в експлуатації:* Статистика кількості кроків для алгоритму Боєра — Мура завжди нульова, що спотворює результати порівняння та візуалізації.

7. **`src/utils/data_structures/test.ts`, рядок 17:**
   - *Дефект:* `elAfterMax: ds.find((ds.findIndex(ds.findMax()) || ds.length) + 1)`.
   - *Загроза в експлуатації:* Якщо максимальний елемент знаходиться за індексом `0`, вираз `0 || ds.length` повертає `ds.length` через те, що `0` є falsy у JavaScript. У результаті запитується елемент за індексом `ds.length + 1` (за межами структури), повертаючи `null`.

8. **`src/utils/data_structures/linkedList.ts`, рядки 46–56 та `doublyLinkedList.ts`, рядки 59–70:**
   - *Дефект:* У методі `remove` при видаленні останнього елемента (хвоста) покажчик `this._tail` не оновлюється на попередній вузол.
   - *Загроза в експлуатації:* Покажчик хвоста залишається посилатися на відв'язаний вузол. Наступні операції `add` приєднують новий вузол до мертвого вузла, ламаючи зв'язність списку і безповоротно втрачаючи нові елементи.

9. **`src/pages/DataStructuresPage.tsx`, рядок 28:**
   - *Дефект:* У мапі класів структур даних `tree: StackDS`.
   - *Загроза в експлуатації:* При переході на маршрут дерева спроба виконати статистику або операцію над деревом інстанціює стек замість дерева.

## 2. Надійність (Reliability)

1. **`src/pages/Home.tsx`, рядки 19–33:**
   - *Дефект:* Призначення обробника подій `onkeydown = (e) => { ... }` на глобальний об'єкт `window` без функції очищення у `useEffect`.
   - *Загроза в експлуатації:* Обробник клавіш продовжує діяти після переходу на будь-яку іншу сторінку застосунку. Натискання клавіш ArrowUp, ArrowDown або Enter на інших сторінках несподівано перехоплюється і спричиняє небажану навігацію.

2. **`src/pages/Home.tsx`, рядки 15, 38:**
   - *Дефект:* Виклики `setTimeout` без збереження ідентифікатора та виклику `clearTimeout` при розмонтуванні.
   - *Загроза в експлуатації:* Витік пам'яті та спроба виклику `setState` / встановлення фокусу на розмонтованому компоненті (React memory leak warning).

3. **`src/utils/sorts/generateArray.ts`, рядки 6–16, 49–53, 96–98:**
   - *Дефект:* Виклики зовнішнього API `fetch("https://randomuser.me/api/")` без обробки помилок `try/catch`, перевірки статусу `response.ok` чи обмеження тайм-ауту.
   - *Загроза в експлуатації:* За відсутності інтернет-з'єднання, перевищення ліміту запитів або збою стороннього сервісу застосунок зазнає падіння з необробленим винятком, а UI блокується. При `length = 50` запускається 50 одночасних мережевих HTTP-запитів.

4. **`src/utils/data_structures/circularList.ts`, рядки 48, 71:**
   - *Дефект:* Використання `while (currentNode)` для обходу кільцевого списку у методах `remove` та `contains`.
   - *Загроза в експлуатації:* Оскільки список замкнений у кільце (`tail.next === head`), якщо шуканий елемент відсутній у списку, цикл стає нескінченним. Це призводить до 100% навантаження на процесор і повного зависання вкладки браузера.

5. **`src/utils/data_structures/RedBlackTree.ts`, рядки 267–272 (`fixDoubleRed`):**
   - *Дефект:* Якщо `i < 2`, вираз `path[i - 2]` повертає `undefined`. Перевірка `if (v === null || w === null)` не відловлює `undefined` (бо `undefined === null` є `false`).
   - *Загроза в експлуатації:* Подальший доступ `w.left` викликає `TypeError: Cannot read properties of undefined (reading 'left')`, що призводить до падіння операції вставки у червоно-чорне дерево.

6. **`src/utils/workerBuilder.ts`, рядки 5–6:**
   - *Дефект:* Створення URL об'єкта через `URL.createObjectURL(blob)` без подальшого звільнення через `URL.revokeObjectURL` і без завершення воркера (`worker.terminate()`).
   - *Загроза в експлуатації:* При кожному запуску порівняння сортувань створюється новий екземпляр воркера та blob-посилання в пам'яті. Це спричиняє витік оперативної пам'яті та накопичення активних фонових потоків.

7. **`src/components/sorts/SortComponent.tsx`, рядки 38–46:**
   - *Дефект:* Конструкція `return new Promise(async () => { ... })` — антипатерн; функція-виконавець є асинхронною, `resolve` ніколи не викликається, а винятки всередині не обробляються.
   - *Загроза в експлуатації:* Проміс зависає у стані `pending`, помилки стають `unhandled rejections`, а при демонтажі компонента відсутній механізм зупинки/скасування сортування.

## 3. Безпека (Security)

1. **`src/utils/workerBuilder.ts`, рядки 4–5:**
   - *Дефект:* Перетворення коду у рядок через `worker.toString()` та виконання через blob: `new Blob(['(' + code + ')()'])`.
   - *Загроза в експлуатації:* Динамічне створення виконуваного коду без суворої CSP (Content Security Policy). Якщо вхідні параметри або скрипт будуть скомпрометовані чи підмінені, це може призвести до виконання довільного коду у фоновому потоці.

2. **`src/utils/sorts/sorts.ts`, рядки 114–116 (`countingSort`):**
   - *Дефект:* Створення масиву розміром `max - min + 1`: `new Array(max - min + 1).fill(0)` без валідації діапазону.
   - *Загроза в експлуатації:* Якщо у вхідному масиві з'явиться велике число (наприклад, $10^9$) або негативні розбіжності, виникає `RangeError: Invalid array length` або виділяються гігабайти пам'яті, спричиняючи відмову в обслуговуванні (Denial of Service).

3. **`src/utils/sorts/sorts.ts`, рядок 108:**
   - *Дефект:* Використання блокуючого модального вікна `alert("Counting sort only works with numbers")` безпосередньо в коді обчислювальної функції.
   - *Загроза в експлуатації:* Блокує потік виконання; за умови виконання у середовищі вебворкера або тестах Node.js викликає фатальну помилку `ReferenceError: alert is not defined`.

## 4. Читабельність (Readability)

1. **`src/utils/sorts/generateArray.ts`, рядки 18–125:**

   - *Дефект:* Орфографічна помилка у назві стану `showTittle` замість `showTitle`.
   - *Загроза в експлуатації:* Дезорієнтація розробників при читанні та модифікації коду.

3. **`src/components/data_structures/Tree.tsx`, рядок 39:**
   - *Дефект:* Використання застарілого ключового слова `var value` замість `const`/`let`.
   - *Загроза в експлуатації:* Ризик витоку області видимості змінної за межі блоку та порушення сучасних стандартів TypeScript/ES6+.

4. **`src/components/SizeForm.tsx`, рядок 1 та `src/pages/DataStructuresPage.tsx`, рядок 7:**

## 5. Тестопридатність (Testability)

1. **`src/components/sorts/SortComponent.tsx`, рядки 8, 36–47:**
   - *Дефект:* Жорстке зв'язування з `useOutletContext()`, `performance.now()` та внутрішніми `setTimeout`.
   - *Загроза в експлуатації:* Неможливо протестувати візуалізатор сортувань ізольовано через передачу пропсів без створення повного мок-контексту маршрутизатора React Router.

2. **`src/utils/workerBuilder.ts`, рядок 1:**
   - *Дефект:* Безпосереднє наслідування від глобального браузерного `Worker` та виклики `URL.createObjectURL`.
   - *Загроза в експлуатації:* У середовищі тестування (Jest / jsdom / Node.js) клас `Worker` та API `URL.createObjectURL` відсутні, що призводить до падіння модульних тестів без ручного глобального мокінгу.

3. **`src/utils/sorts/sorts.ts`, рядки 4–5, 81, 89:**
   - *Дефект:* Мутабельні змінні стану рівня модуля (`IS_ASC`, `STEPS`).
   - *Загроза в експлуатації:* Унеможливлює паралельне або ізольоване тестування кількох алгоритмів сортування у тестовому раннері, оскільки виклики впливають на спільний стан.
